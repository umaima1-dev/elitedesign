Before you start

You need Claude Code installed and logged in on your computer. That’s the only thing Clip It leans on. If you already use Claude Code, you’re set.

Setup installs everything else for you (Python, Node.js, ffmpeg and a couple of small helpers) if they’re missing.

Get it running in 3 steps

1

Download it

On the GitHub page, click the green Code button, then Download ZIP. Unzip it somewhere you’ll find it again, like your Documents folder.

Comfortable with Git? Clone it instead.

Open Clip It on GitHub →

2

Run setup once

Open a terminal in the folder, then run the command for your computer.

Mac or Linux: open Terminal in the folder
./setup.sh
Windows: open PowerShell in the folder with setup.ps1
powershell -ExecutionPolicy Bypass -File .\setup.ps1

You’re ready when it says All good ✔. If Windows tells you a tool “is not on PATH yet”, close PowerShell, open a new one and run the same command again. That’s normal the first time.

3

Make your first reels

Start the dashboard.

Mac or Linux
./reels dashboard
Windows
Double-click dashboard.cmd

Your browser opens. Paste a YouTube link to an episode, choose how many reels you want, and press Make reels. They’ll appear as cards you can play, download and copy the caption from.

What to expect on your first run

The first video takes longer because Clip It downloads its speech model once (about 0.5 to 1.6 GB, depending on your computer). After that it’s quicker.

A one-hour episode transcribes in roughly the times shown, and rendering adds a bit on top. Start it, go do something else, and come back to reels.

One-hour episode, transcribedNewer Mac or a PC with an NVIDIA graphics card
2 to 8 min
One-hour episode, transcribedOrdinary laptop
15 to 40 min

If something gets stuck

YouTube says “Sign in to confirm you’re not a bot”.

Open config.yaml and set cookies_from_browser to the browser you use (chrome, firefox, edge or safari).

Renders are slow or stall on a laptop.

That’s usually too much running at once. The Troubleshooting section at the bottom of the GitHub page walks you through it, along with the other common fixes.
